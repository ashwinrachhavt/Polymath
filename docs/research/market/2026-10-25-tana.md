# Market research: Tana / Tana Outliner

**Date:** 2026-10-25 · **Analyst:** overnight build session · **Status:** current as of 2026-10-25 sources
**Category:** PKM outliner (Supertags) - and a cautionary pivot.

## The headline: Tana left the category

Tana, the most technically admired PKM of the 2020-2024 wave, is no longer a
PKM product. The brand's flagship is now **Tana, an agentic meeting platform**
(native video calls where AI agents act during the meeting and file outcomes
into a "context graph"). The original outliner survives as **Tana Outliner**
at outliner.tana.inc. The company's own positioning is explicit: agents doing
real work during conversations, not people organizing notes afterward. [S1][S2]

This is a market signal, not just a product fact: the two most agentic
PKM-native companies (Tana, Mem) both concluded that *note organization is
not the product* - **agent action over accumulated context is.**

## Tana Outliner today (verified 2026-10-25)

- **Infinite outliner**: every bullet is a node; zoom any node into a page;
  nodes appear in multiple places as references that stay in sync. [S2]
- **Supertags**: turn a node into a typed object with a field template;
  same-tag nodes form searchable, filterable, table-viewable collections.
  This is the schema layer competitors cite constantly. [S2]
- **Daily notes / week / month / year nodes** with templates; @-mention a
  date and the node appears on that calendar node. [S2]
- **Command line (Cmd/Ctrl+K)** with custom keyboard shortcuts for any
  command. [S2]
- **Checkboxes with automatic progress bars** aggregating up the hierarchy. [S2]
- Workspaces with per-workspace schema, library, and settings. [S2]

## The new Tana (agentic meetings), as positioning worth studying

- Native video call + agents with **the same tools as human participants**
  (screen share, doc editing, canvas) acting in real time. [S1]
- **Skills**: codified agent workflows authored in natural language. [S1]
- **Context graph** populated automatically from meetings, with **merge
  proposals** (diffs shown, human approves) to keep memory accurate - their
  answer to "AI slop" in append-only systems. [S1]

## What Axiom can assimilate

1. **Supertags' core insight, already in Axiom's shape**: typed things with
   structure (Axiom's domains + capture_proposal_kind) beat untyped pages.
   The Outliner validates the type catalog direction (ASH-272).
2. **Merge proposals with diffs and human approval.** This is the strongest
   single idea in the new Tana: agents may EDIT the graph, but every edit is
   a reviewable diff. Axiom's proposal pattern (never applied silently) is
   the same philosophy - extend it from "create proposals" to "merge/update
   proposals" as the graph grows duplicates. (Proposal tables already carry
   payload + rationale + status; a merge kind is additive.)
3. **Progress bars over nested checkboxes** - the daybook/projects surfaces
   could aggregate completion the same cheap way.
4. **Week/month/year nodes** as first-class time containers: the daybook is
   the day; weekly reviews exist; the calendar hierarchy above them is thin.
5. **Skills authored in natural language** - Axiom's Skills system already
   has the codified-workflow half; NL authoring is the UX lesson.

## Where Axiom can differentiate

1. **The meeting pivot left personal knowledge unattended.** Tana now needs a
   video call to create context; Axiom builds context from everything
   (captures, documents, email, reading) without requiring meetings.
2. **Verified claims** (quote-checked zettels) vs. transcripts summarized by
   agents in real time - speed vs. provability.
3. **Free-first, registry-gated costs** vs. a venture-backed pivot whose
   pricing follows the agent-metering trend.
4. **Solo-first**: Tana's new shape is team meetings; Axiom is one person's
   operating system.
