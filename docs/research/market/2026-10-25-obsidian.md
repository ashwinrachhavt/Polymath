# Market research: Obsidian

**Date:** 2026-10-25 · **Analyst:** overnight build session · **Status:** current as of 2026-10-25 sources
**Category:** local-first Markdown knowledge base; the incumbent "second brain."

## What it is

The category-defining local Markdown note app: notes as files on your device,
a wiki-link graph, an enormous plugin/theme ecosystem, and paid first-party
add-ons (Sync, Publish) instead of a subscription app. Positioning: "private
thoughts," offline-first, no lock-in, "you own your data for the long term." [S1]

## Current feature set (verified 2026-10-25)

- **Local Markdown vaults**, offline-first; no sign-up required. [S1]
- **Wiki-links + interactive graph view**; Canvas (spatial infinite board for
  research/brainstorm/diagramming). [S1]
- **Bases**: database-style views over notes and their properties - tables,
  filters, and views defined in a documented syntax - bringing Notion-like
  structured views to local files. [S2]
- **Thousands of community plugins and themes**; the plugin API is the real
  product surface for power users. [S1]
- **Sync** ($4/user/mo annual): E2E-encrypted, one-year version history,
  selective per-file sync, shared-vault collaboration. [S1][S3]
- **Publish** ($8/site/mo annual): notes to a fast themed site with graph and
  full-text search. [S3]
- Catalyst ($25 one-time, early access) and Commercial ($50/user/yr,
  honor-system) licenses fund the indie team. [S3]

## Business model

100% user-supported: free app, paid add-ons and licenses. No AI features
first-party - AI arrives through community plugins and the user's own keys. [S3]

## Strengths

- **Ownership story** the market trusts: open format, offline, outlives the
  company. Every competitor's pitch (including Reflect Open's) is measured
  against it.
- **Ecosystem gravity**: plugins cover most long-tail workflows; users
  assemble their own personal OS.
- Bases closes the "structured data" gap against Notion without leaving files.

## Weaknesses

- **DIY everything**: capture automation, classification, task management,
  agents, and AI all require assembly from plugins; the default app is a
  passive editor.
- No server side at all: no background processing, no outbox, no scheduled
  work, no cross-device automation beyond file sync.
- Graph visualization is decorative for most users; links are page-level,
  not claim-level.

## What Axiom can assimilate

1. **Bases-style saved views.** Structured, named, filtered views over
   domain data (tasks, notes, captures) as a first-class, shareable artifact.
   Axiom's Work surface already has filters; a "saved view" object would
   generalize it. (Work data: `src/app/(workspace)/command-center/`.)
2. **Canvas precedent for the spatial-canvas ticket** (ASH-307, a direction
   call): Obsidian proves spatial layout is a beloved secondary surface, not
   the primary one. Evidence for the morning discussion.
3. **The file-export guarantee.** Even as a server app, a one-click export to
   plain Markdown vault would neutralize the lock-in objection Obsidian
   owns. The extraction/artifact model already stores Markdown-native
   content.
4. **Version history as a paid-tier-worthy feature** - Axiom's document
   versioning already exists; surfacing it like Sync does is the lesson.

## Where Axiom can differentiate

1. **A server that works while you sleep**: outbox-driven enrichment,
   classification, embeddings, and proposals - Obsidian's architecture makes
   this structurally impossible without a plugin + a always-on machine.
2. **Verified claims and evidence rows** vs. page links; claim-level
   retrieval (hybrid RRF with citations) vs. full-text + graph.
3. **Agents with a tool surface** (Eve) operating over typed domains, vs.
   plugins scripting an editor.
4. **Action domains** (tasks, CRM, calendar, spending) in the same graph -
   Obsidian users assemble this from Dataview/Tasks/Projects plugins and
   pray.
