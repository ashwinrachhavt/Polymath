### Global authentication limitation

The middleware's matcher includes `/`, dashboard, boards, todos, profile, pomodoro, gamify and API/TRPC; **it omits calendar, events, tasks, reports, settings, chat, debug, sign-in and sign-up** (`N/src/middleware.ts:48–60`). Its signed-out page branch intentionally does not redirect (`:35–44`), while all matched APIs get JSON 401. Pages calling Clerk `auth()` outside matched routes may fail to receive middleware context; pages without their own auth can render while their APIs reject. This is a source-backed configuration risk, not a claim of observed browser behavior. Keep server-derived ownership and explicit permission/configuration UI in the shared shell; never port route-auth coverage as-is.

### Explicit state and capability gaps (not silently “implemented”)

- **Loading:** route skeletons exist for dashboard/board/todos, but many client-query loaders are blank or indefinite. **Empty:** some invitations exist; failures often appear empty. **Error:** route reset/toasts/inline request errors are uneven and do not cover silent catches. **Success:** many optimistic “success” presentations are premature or unrelated to persisted state. Evidence in per-feature tables above.
- **Partial/stale/offline/conflict:** no coherent shared state model, offline banner, sync health, stale-write handling or partial collection marker. Bounds silently omit tasks (50 per board or100 current todos), while full board collections unbounded (`N/src/app/api/me/boards/route.ts:18–20`; `N/src/app/api/tasks/my/route.ts:11–22`; `N/src/server/db/cards.ts:11–13`).
- **Permission/configuration:** Clerk/401 checks are present, but no consistent permission-denied or model/database/connector configuration screen; missing middleware and unsafe tools remain blocking. No donor browser preview should simulate successful AI, syncing, extraction, claims or provider writes.
- **Undo/recovery:** no version history, audited rollback, reliable draft recovery, mutation receipts, idempotent completion/reward, or durable assistant retry/resume. The existence of AgentRun/AIEvent/AgentOutput is logging, not a user-facing durable run/approval system (`N/prisma/schema.prisma:439–476`; `N/src/server/db/agentRuns.ts:4–22`).
- **Accessibility:** preserve keyboard pathways only when real; add a keyboard alternative to every move/rank gesture, labels for icon controls, stable overlay focus/return, text for graphs/rewards/timers, reduced motion and disable celebration. Source-backed deficiencies are not waived by PRD performance/accessibility aspirations (`N/docs/PRD.md:128–132`; `A/agents/design.md:215–230`).
- **Absent actual screens:** team/collaboration, integration connection/account selection, Pro/billing, deletion account, full project manager, document import/extraction/search, graph navigator, flashcard review, quiz-taking, meeting management, stats sharing, policy/budget/history, durable run questions/reviews. Keep only in-scope canonical Axiom journeys, not every donor mockup experiment.
